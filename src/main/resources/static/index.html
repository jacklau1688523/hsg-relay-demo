C1 业务准入 · 合作方动态规则路径

C1 按候选合作方选择路径（P1 / P2 / … / DEFAULT），只执行该路径自己的条件树，再执行对所有路径都生效的全局必检。 准入规则、客户排除、个案审批和 MTD 在合作方详情页维护；这里配置路径、模拟判定、查看历史版本。

C1 判定顺序（每个候选合作方都按这个顺序执行，首个失败项决定原因码）

⓪
读取路径配置只读已发布的版本。从未发布 → C1_CONFIG_MISSING；版本读不出来、启用的路径没有条件树 → C1_CONFIG_BROKEN。都按拒绝处理，不会默认通过。
①
客户档案读取客户分类状态和流转类别；档案不存在 → CLIENT_NOT_FOUND。
②
路径选择（FIRST_MATCH，按 candidate.providerCode）启用的专用路径里恰好一条绑定了该合作方 → 用它；一条也没有 → DEFAULT 路径；多条 → C1_PATH_CONFLICT；DEFAULT 未启用 → C1_PATH_NOT_FOUND。优先级只决定列表顺序，不参与选路。
②
路径条件 <流转类别>（所选路径自己的条件树）只执行所选路径的条件树，每个流转类别分别求值；不满足即按这条路径的失败原因码过滤，不落到其它路径。DEFAULT 也要过自己的条件树，不是自动通过。
③
客户分类（必检）分类状态须为 COMPLETE，否则 CLIENT_NOT_CLASSIFIED。
③
客户排除（必检）客户在合作方的有效排除记录中 → CLIENT_EXCLUDED；排除记录查不出来 → CLIENT_EXCLUSION_CHECK_FAILED（不按「未排除」放行）。
③
规则匹配 <流转类别>（APPETITE_MATCH，必检）对每个流转类别在合作方准入规则里按四级匹配：精确币种+精确国家 ＞ 精确币种+ALL ＞ ALL+精确国家 ＞ ALL/ALL；高一级里有命中的规则就不再看低一级，不会退到低级别。无命中 → APPETITE_NOT_SET；命中 EXCLUDE → APPETITE_EXCLUDED。
④
个案审批 / MTD（必检）命中 CASE_BY_CASE 须有有效审批（APPETITE_APPROVAL_MISSING）；命中设有月度上限的 ACCEPT 规则时校验 MTD + 本笔金额（APPETITE_CAP_REACHED）。
⑤
C1 汇总全部流转类别通过路径条件和必检 → PASS。
系统必检清单（代码级，只读）
C1 执行器在代码里直接执行这些检查，不读函数库元数据，也不看路径条件树里有没有对应的节点：停用函数、删除条件节点都绕不过。可以把其中的函数加到路径条件树参与比较，删除节点只是不再比较它的返回值。
从旧版「全局准入条件」迁入的说明
旧版全局准入条件的两个布尔条件（appetiteCurrencyEnabled / appetiteCountryEnabled）已由 APPETITE_MATCH 四级匹配取代。迁移只生成草稿和只读的 v1 快照，不改写旧配置；下列提示在第一次发布后清空。

路径清单

每条路径绑定若干合作方，有自己的条件树和失败原因码。修改从草稿开始：保存草稿不参与判定，发布后生成新的不可变版本，C1 只读已发布版本。已发布过的路径不能删除，可以停用。

条件树：

点击路径卡片上的「编辑条件」，这条路径的条件树就挂在下面的编辑器里（字段库 + 函数库，与原来的全局条件编辑器是同一个）。修改先留在页面上，保存草稿后才写入草稿。
点击「校验并生成表达式」查看每条路径的可读表达式
模拟要素 ⓘ
试算只读：不写任何数据、不占用 MTD。「按已发布版本校验」与 C1–C10 Check 用的是同一份已发布版本；「按当前页面草稿试算」用「合作方路径配置」页签上现在的内容（不必先保存），结果里的规则版本显示为草稿。

ƒ 添加函数

选择函数，配置参数绑定、比较方式和期望值，再加入当前条件组。参数可引用受控取值路径（$ 开头，输入框有候选）或填写字面量；集合类函数（如 collectionContains）的参数按「来源 + 绑定」显式选择：集合字段取元数据字段（如合作方有效排除客户集合），比较元素取本笔交易 / 候选合作方 / 规则上下文。保存时由服务端校验。
